Layer I — Hosting

STRUCTURAL PARASITISM

The original payload was injected into a proprietary CMS (Weebly). This GitHub Pages file is the extracted node: no host footer to hide, no killWeebly() routine.

Then: CSS !important and a MutationObserver hid .wsite-footer in the browser. Client-side DOM only — it never touched Weebly's server.
Now: Standalone HTML on GitHub Pages. No CMS chrome. The audit below remains, because the pattern still describes how the site was built.
Layer II — UI/UX

COGNITIVE STIMULATION

The “terminal / technical dossier” aesthetic is psychological anchoring, not a running system.

Typography: Bebas Neue, Libre Baskerville, IBM Plex Mono — printed-report pairing, not a console.
Chromatic: High contrast on black. Gold for structure; alert red for warning blocks.
Motion: This file has no looping I/O animation. Static document.
Layer III — Site Pattern (not present in this file)

THE TEMPORAL ENGINE

This file contains no countdown and no setInterval. The following describes a pattern used on other historical nodes, for context.

Mechanism (elsewhere): Delta between Date.now() and a hardcoded timestamp, refreshed every 1000 ms.
Degradation (elsewhere): Below a threshold, bar color and warning styles mutate.

Where it existed, it was not a “singularity clock”. It was a cognitive urgency timer. This file does not implement that mechanism.

Layer V — Site Pattern

DEPLOYMENT AND INJECTION

This file has one outbound action: a plain anchor.

No clipboard write, no window.open, no auto-redirect. Clipboard-to-prompt buttons on other historical nodes primed a model's context window; they did not change model weights. This file does not do that.

This file implements no perimeter defense. No contextmenu block, no copy intercept, no user-select: none. Text can be selected normally.
